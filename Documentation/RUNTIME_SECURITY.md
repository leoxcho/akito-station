# Runtime security policy and remaining gates

Automatic release selection is limited to the exact catalog releaseRepository. Asset URLs must use HTTPS github.com and that repository's releases/download path, with exact filename identity. Metadata API redirects are refused. Asset redirects permit only github.com, release-assets.githubusercontent.com and objects.githubusercontent.com over HTTPS, no userinfo/custom port. Expected positive asset size is capped at 2 GiB before/while download; optional GitHub SHA-256 digest is checked exactly when supplied. Digest availability/official publisher checksum for each real upstream needs live acceptance; not every release provides a checksum.

Automatic extraction supports non-encrypted, non-multipart, non-ZIP64 ZIP without symlink entries. Preflight validates local/central name identity, range bounds, path/duplicate names, at most 100,000 entries, 8 GiB expanded data and a 200:1 per-entry ratio above the 1 MiB small-entry allowance. System ditto extraction is staged, followed by file/size/symlink checks. Failed staging is removed. Legitimate incompatible archives use official manual extraction and native app import. Limits are RuntimeArchiveLimits values; changes require tests/review.

Native app import requires catalog emulator identity and platform match, Mach-O executable detection and bundle-contained paths. Original and managed copies remain unchanged; no automatic ad-hoc re-signing occurs. Existing signatures must verify deeply/strictly. All regular bundle files and internal symlink targets are fingerprinted and rechecked at selection/launch, covering nested dylib/resource changes and unexpected new files. UI reports unsigned, ad-hoc or signed publisher-unverified state. Ad-hoc signatures are never publisher proof. Unsigned official upstream builds are allowed as an explicit unverified trust state, not falsely described as trusted signed builds.

The Team ID policy rejects wrong/unsigned/ad-hoc artifacts when an expected stable publisher is supplied. **No stable per-upstream Team ID baseline is yet configured/verified.** Do not guess identities or claim B8 cleared. Owner/reviewer must inspect genuine official builds for each automatic catalog emulator, document stable Team IDs/bundle identifiers (when provided), pin those in a reviewed policy, and run actual signed/unsigned/tampered release acceptance. Checksum fixtures and policy tests are not full live upstream certification. A compromised unsigned upstream without authenticated checksums/signature cannot be distinguished by local self-recorded hashes alone.

Remaining legacy helper scripts are not the default native catalog app/core/ZIP import routes. Optional source builds require Python/git/make/cmake/clang/lipo and dependencies; PS3/Vita package installation now uses native isolated staging and the user-installed emulator, with user-supplied firmware/licenses; extracted PS4 folder import is native. Real upstream package acceptance remains unverified. Settings import uses native selective graphics/controller merging; unsupported configuration types direct the user to the emulator's own interface.

Continuation: ZIP payloads are now extracted natively through the macOS libz dependency using fixed 64 KiB buffers. Each entry is capped at its declared expanded size before bytes are written; total declared output is bounded, and CRC/compressed-stream completion must agree. Stored and deflated entries are supported; symlink/special modes, encryption, multipart and ZIP64 remain unsupported. Explicit plus implicit parent paths count toward the file budget. Directory/header interval checks reject overlaps. No symlink or hardlink objects are created, so archive link metadata cannot redirect writes. Failed/canceled stages are removed. Available space must cover declared output plus configurable reserve; disk writes fail closed if space disappears after preflight. Nested archive files remain opaque and are never recursively unpacked. An app inside a nested archive requires manual official extraction/import.

Native bounded extraction and official checksum sidecar policy supersede the former ditto/preflight-only path. Refer to RUNTIME_TRUST_POLICY.md for exact status meanings and remaining upstream publisher-baseline limitations.
